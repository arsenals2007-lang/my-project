# Вариант 18: эмулятор оболочки

Практическая работа по конфигурационному управлению, ИКБО-51-25.
Python 3.10+, только стандартная библиотека; macOS, Linux.

## Этап 1

Консольный REPL показывает реальные имя пользователя и имя компьютера.
Парсер раскрывает `$NAME` и `${NAME}`, поддерживает кавычки и экранирование.
В одинарных кавычках переменные не раскрываются. Значение переменной
остается частью одного аргумента, даже если содержит пробелы.
Неизвестная переменная дает пустую строку. Команды ОС не запускаются.

`ls [путь]` и `cd [путь]` пока выводят свое имя и аргументы.
`exit` завершает сеанс. Неизвестные команды, лишние аргументы и незакрытые
кавычки выводят ошибку. Ctrl+D завершает сеанс, Ctrl+C отменяет ввод.

## Запуск и тесты

Сборка и установка пакетов не нужны:

```sh
sh run.sh
make test
```

Переопределить интерпретатор: `PYTHON=/путь/к/python3 sh run.sh`.

## Демонстрация первого этапа

Ввести последовательно:

```text
ls

cd $HOME
cd '$HOME'
unknown
cd a b
ls "unfinished
exit extra

```

В `src/shell18/parser.py` находятся `parse_command` и `expand_variable`.
В `src/shell18/shell.py` класс `Shell` управляет сеансом, приглашением,
исполнением строк и циклом REPL. `__main__.py` запускает программу.

## Этап 2: настройки и стартовый скрипт

`--vfs путь` задает источник VFS (на этом этапе путь только выводится).
`--script путь` задает текстовый файл команд в UTF-8.
`--batch` отключает REPL после стартового скрипта.
`--help` показывает справку. Пути относительны текущей папке реальной ОС.
При запуске печатаются все настройки. Файл конфигурации не требуется.

Скрипты поддерживают комментарии `#` вне кавычек. Показываются приглашение,
ввод, вывод и номер строки при ошибке. Исполнение продолжается после ошибок;
`exit` завершает скрипт и сеанс. Код выхода 1 означает ошибку скрипта,
код 2 — ошибку аргументов запуска; успешное исполнение возвращает 0.

```sh
sh run.sh --vfs examples/minimal.xml --script examples/stage2.shell
sh scripts/test_config.sh
sh scripts/test_errors.sh
```

`read_options` разбирает аргументы, `main` управляет запуском,
`run_script` исполняет стартовый файл.

## Этап 3: VFS

XML читается один раз, узлы и байты хранятся в памяти. Исходный файл
не меняется. Если `--vfs` отсутствует, создается пустой корень в памяти.
Ошибка чтения или формата VFS завершает программу с кодом 1.
`examples/minimal.xml`, `files.xml`, `deep.xml` демонстрируют пустую ФС,
несколько файлов и более трех уровней вложенности.

```xml
<vfs name="example">
  <directory name="home" owner="student" group="students">
    <file name="note.txt" encoding="utf-8">Текст</file>
    <file name="data.bin" encoding="base64">AAEC/w==</file>
  </directory>
</vfs>
```

`name` обязателен у каждого файла и каталога; `/`, `.` и `..` запрещены
в именах. `owner` и `group` по умолчанию равны `user` и `users`.
У файла `encoding` равен `utf-8` (по умолчанию) или `base64`.
Имена в одном каталоге уникальны. Неизвестные элементы, атрибуты,
кодировки, DTD, некорректный base64 и текст внутри каталога отвергаются.

`Node` хранит тип, байты и владельца; `VFS.load` загружает источник;
`validate_element`, `file_data`, `load_children` проверяют схему.
`VFS.resolve` обрабатывает абсолютные и относительные пути, `.` и `..`;
выход выше корня остается в `/`. `VFS.children` перечисляет прямые узлы.

```sh
sh scripts/test_vfs.sh
sh run.sh --vfs examples/deep.xml --script examples/stage3.shell --batch
```

Скрипт stage3 содержит намеренные ошибки и возвращает код 1.

## Этап 4: основные команды

| Команда | Поддерживаемое поведение |
| --- | --- |
| `ls [-a] [-l] [путь]` | Отсортированные имена, скрытые узлы, тип/владелец/группа/размер |
| `cd [путь]` | Сменить каталог; без аргумента перейти в `/` |
| `cd -` | Перейти в предыдущий каталог и показать путь |
| `pwd` | Напечатать абсолютный виртуальный путь |
| `tree [-a] [путь]` | Рекурсивное дерево, по умолчанию без скрытых узлов |
| `cal` | Текущий месяц по дате ОС |
| `cal год` | Весь год от 1 до 9999 |
| `cal месяц год` | Месяц от 1 до 12; учитываются високосные годы |
| `exit` | Завершить сеанс |

Короткие флаги объединяются: `ls -al`. Разделитель `--` разрешает
передавать пути с начальным `-`. У `ls` и `tree` поддерживается один путь.
`ls -a` показывает реальные скрытые узлы без синтетических `.` и `..`.
В `ls -l` размер — число байтов, у каталога 0; права и даты не моделируются.
Календарь использует английские названия, неделя начинается с понедельника.
Все пути команд относятся к VFS. `$HOME` раскрывается из реальной ОС,
поэтому `cd $HOME` успешен только при наличии такого пути внутри VFS.

`Commands` хранит обработчики; методы `ls`, `cd`, `pwd`, `tree`, `cal`,
`exit` исполняют команды; `print_tree` выводит вложенные узлы.
`parse_options` разбирает флаги, `check_count` проверяет число аргументов.

```sh
sh run.sh --vfs examples/deep.xml --script examples/demo.shell --batch
sh run.sh --vfs examples/deep.xml --script examples/stage4.shell --batch
```

`stage4.shell` содержит проверки ошибок и возвращает код 1.
Сценарии предыдущих этапов следует запускать на соответствующем git-теге:
после замены заглушек команды проверяют существование виртуальных путей.
