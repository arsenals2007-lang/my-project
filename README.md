# Вариант 18 - эмулятор командной оболочки

Практическая работа №1 по конфигурационному управлению, группа ИКБО-51-25.
Решение на Python 3.10+ по варианту №18 из сборника
«ИКБО-51-25-2.pdf», страницы 59-61. Реализованы все пять этапов:
консольный REPL, конфигурация, XML VFS, основные и дополнительные команды.

Адрес репозитория для публикации:
[arsenals2007-lang/my-project](https://github.com/arsenals2007-lang/my-project).
Для сдачи в СДО нужны URL открытого репозитория и PDF-версия этого README.

## Запуск

Нужен Python версии 3.10 или новее. Используется только стандартная
библиотека, установка пакетов и сборка не требуются. Команды ниже выполнять
из каталога проекта в терминале macOS или Linux:

```sh
python3 --version
sh run.sh --vfs examples/deep.xml
```

Приглашение имеет вид `username@hostname:/$ `: имя пользователя и имя
компьютера берутся из реальной ОС, путь относится к виртуальной ФС.
`exit` и Ctrl+D завершают сеанс, Ctrl+C отменяет текущий ввод.

```sh
# Успешный сценарий с основными и дополнительными командами.
sh run.sh --vfs examples/deep.xml --script examples/demo.shell --batch
# Проверка всего набора автоматических тестов.
make test
```

Без `make`: `PYTHONPATH=src python3 -m unittest discover -s tests -v`.
Для другого интерпретатора: `PYTHON=/путь/к/python3 sh run.sh` или
`make test PYTHON=/путь/к/python3`.

| Параметр запуска | Значение |
| --- | --- |
| `--vfs путь` | XML-файл - источник виртуальной ФС; без него создается пустой корень `/` |
| `--script путь` | Стартовый файл команд в UTF-8; без него команды читаются интерактивно |
| `--batch` | Завершить программу после скрипта, не входя в REPL |
| `--help` | Показать справку и завершить программу |

Пути параметров `--vfs` и `--script` относятся к реальной ОС и разрешаются
относительно каталога запуска. При обычном запуске выводятся все три
настройки `[config]`. Если после скрипта не было `exit` и не указан
`--batch`, начинается интерактивный сеанс.

## Команды и разбор строк

| Команда | Назначение и режимы |
| --- | --- |
| `ls [-a] [-l] [путь]` | Перечислить содержимое каталога или указанный файл; `-a` включает скрытые узлы, `-l` показывает тип, владельца, группу и размер в байтах |
| `cd [путь]` | Сменить виртуальный каталог; без пути перейти в `/` |
| `cd -` | Перейти в предыдущий каталог и вывести его путь |
| `pwd` | Вывести абсолютный путь текущего виртуального каталога |
| `tree [-a] [путь]` | Вывести дерево; `-a` включает скрытые узлы; для файла вывести его путь |
| `cal` | Вывести текущий месяц по дате реальной ОС |
| `cal год` | Вывести весь указанный год, от 1 до 9999 |
| `cal месяц год` | Вывести месяц от 1 до 12 указанного года |
| `mkdir [-p] путь [путь ...]` | Создать один или несколько виртуальных каталогов; `-p` создает родителей и допускает существующий каталог |
| `chown [-R] владелец[:группа] путь [путь ...]` | Изменить виртуального владельца/группу; `-R` включает всех потомков |
| `exit` | Завершить скрипт и сеанс; дополнительные аргументы запрещены |

Короткие флаги объединяются: `ls -al`. Разделитель `--` завершает разбор
опций: `mkdir -- -dash` создает каталог с именем `-dash`.
У `ls`, `cd`, `tree` допускается не больше одного пути.
Все пути внутри команд относятся к VFS. Поддерживаются абсолютные и
относительные пути, компоненты `.` и `..`; подняться выше `/` нельзя.
Каждый промежуточный компонент проверяется как каталог.

Имена выводятся в отсортированном порядке. Скрытым считается узел, имя
которого начинается с точки; `ls -a` не добавляет синтетические `.` и `..`.
У каталогов размер равен 0, у файлов - длине байтового содержимого.
Календарь учитывает високосные годы; названия английские, неделя начинается
с понедельника.

Парсер поддерживает одинарные и двойные кавычки, экранирование обратной
косой чертой и переменные реальной ОС `$NAME`, `${NAME}`. В одинарных
кавычках переменные сохраняются буквально. В двойных кавычках обратная
косая черта экранирует `$`, `"`, `\`; перед другими символами сохраняется.
Неизвестная переменная дает пустую строку. Раскрытое значение всегда
остается частью одного аргумента, даже если содержит пробелы.
Символ `#` вне кавычек начинает комментарий, в том числе после команды.

```text
cd "folder with spaces"
cd /
ls $HOME          # значение HOME ищется внутри VFS
ls '$HOME'        # буквальное имя $HOME
ls "unfinished   # ошибка незакрытой кавычки
unknown          # ошибка неизвестной команды
```

`$HOME` не переносит выполнение на реальную ФС: команда с таким путем
успешна только при наличии соответствующего узла в VFS.

Для `chown` поддержаны четыре формы: `alice` меняет только владельца,
`alice:staff` - владельца и группу, `:staff` - только группу, `alice:` -
владельца и группу на `alice`. Новые имена должны состоять из латинских
букв, цифр, `_`, `.`, `-`; реальные учетные записи не проверяются.
`mkdir` назначает владельцем реального пользователя, а группу берет
у родительского виртуального каталога.

## XML и хранение VFS

XML в UTF-8 (допускается BOM) загружается один раз перед исполнением
команд. Каталоги, метаданные
и содержимое файлов хранятся в памяти; файлы из XML не распаковываются.
`mkdir` и `chown` меняют только состояние текущего сеанса. Исходный XML и
каталоги реальной ОС сохраняются без изменений. После нового запуска
изменения предыдущего сеанса отсутствуют.

```xml
<?xml version="1.0" encoding="utf-8"?>
<vfs name="example">
  <directory name="home" owner="student" group="students">
    <file name="note.txt" encoding="utf-8">Привет!</file>
    <file name="data.bin" encoding="base64">AAEC/w==</file>
    <directory name="projects" />
  </directory>
</vfs>
```

Корневой элемент - `vfs`, его необязательный атрибут `name` задает имя
источника. Если он отсутствует, используется имя XML-файла без расширения.
Внутри разрешены `directory` и `file`.

| Атрибут узла | Правило |
| --- | --- |
| `name` | Обязателен; непустое имя, без `/` и нулевого символа; `.` и `..` запрещены |
| `owner`, `group` | Необязательны; по умолчанию `user` и `users`; пустые значения запрещены |
| `encoding` | Только у `file`: `utf-8` по умолчанию или `base64` |

Имена в одном каталоге уникальны. Каталоги могут содержать другие узлы,
файлы - только текст. У UTF-8-файла пробелы и переводы строк входят
в содержимое. У base64-файла пробельные символы удаляются перед строгим
декодированием. Пустой `<vfs />` создает только корень `/`.

Неизвестные элементы/атрибуты, неверные кодировки, ошибочный XML,
дублирующиеся пути, вложенные элементы в файле и некорректный base64
отвергаются. Текст внутри каталога и между узлами допускается только
как пробельное форматирование. DTD, объявления сущностей и XML в UTF-16 не поддержаны.

Готовые источники: `minimal.xml` - пустая ФС; `files.xml` - несколько
текстовых/двоичных файлов; `deep.xml` - дерево с четырьмя уровнями
каталогов, скрытым файлом и именем с пробелами; `invalid.xml` - ошибочный
пример для проверки загрузчика. Все находятся в `examples/`.

## Сценарии, ошибки и проверки

Стартовый скрипт содержит команды эмулятора, по одной в строке.
Пустые строки и строки комментариев пропускаются. Для остальных строк
выводятся приглашение, исходная команда и результат. При ошибке также
печатаются имя скрипта и номер строки; исполнение следующих строк
продолжается. `exit` прекращает чтение оставшихся строк.

| Код завершения | Значение |
| --- | --- |
| `0` | Запуск и скрипт завершились без ошибок |
| `1` | Ошибка чтения/формата VFS, чтения скрипта или хотя бы одной его команды |
| `2` | Неверные параметры запуска, например неизвестная опция |

В интерактивном REPL ошибка команды выводит сообщение и сохраняет сеанс;
сама по себе она не меняет код завершения программы. Неверные параметры
команд, отсутствующие пути и попытки перейти в файл также обрабатываются.

```sh
sh scripts/test_config.sh
sh scripts/test_errors.sh
sh scripts/test_vfs.sh
sh scripts/test_commands.sh
```

Эти сценарии реальной ОС проверяют настройки запуска, ошибки, разные
источники VFS и команды. Они учитывают ожидаемые ошибки, поэтому
успешная проверка сценария возвращает 0, хотя в выводе есть сообщения
`Ошибка`.

```sh
sh run.sh --vfs examples/deep.xml --script examples/stage4.shell --batch
sh run.sh --vfs examples/deep.xml --script examples/stage5.shell --batch
```

Оба примера намеренно содержат неверные команды и должны вернуть 1.
`examples/errors.shell` также проверяет ошибки и продолжение выполнения.
`examples/demo.shell` - успешная демонстрация без намеренных ошибок.
`stage2.shell` и `stage3.shell` относятся к историческим прототипам:
после реализации VFS прежние команды-заглушки стали проверять реальные
виртуальные пути. Их первоначальное поведение следует смотреть на тегах
соответствующих этапов.

`make test` запускает `unittest`: проверяются парсер, REPL и приглашение,
аргументы запуска/скрипты, XML/base64, разрешение путей, режимы всех команд,
обработка ошибок и сохранность исходного XML после изменений VFS.

## Устройство программы и этапы

| Модуль | Классы и функции |
| --- | --- |
| `__main__.py` | `read_options` разбирает запуск; `main` выводит конфигурацию, загружает VFS и запускает сеанс |
| `parser.py` | `expand_variable` раскрывает переменную; `parse_command` возвращает аргументы; `Lexer` хранит состояние кавычек, методы `append`, `flush`, `change_quote`, `escape`, `step` разбирают строку |
| `shell.py` | `Shell`: конструктор хранит состояние; `prompt` формирует приглашение; `execute` выбирает обработчик; `repl` читает команды |
| `startup.py` | `run_script` исполняет файл с отображением диалога и номеров ошибок |
| `vfs.py` | `Node` хранит узел; `validate_element`, `file_data`, `load_children` проверяют XML; `VFS` создает корень, `load` загружает, `resolve` и `walk_component` разрешают пути, `children` перечисляет потомков |
| `options.py` | `parse_options` разбирает флаги/`--`; `check_count` проверяет число аргументов |
| `commands.py` | `Commands` регистрирует `ls`, `cd`, `pwd`, `tree`, `cal`, `exit`; `print_tree` печатает дерево через явный стек |
| `mutations.py` | `ownership`, `validate_identity` проверяют владельца/группу; `directory_component`, `make_directory` создают каталоги; `Mutations` регистрирует `mkdir`, `chown` |

Исходники находятся в `src/shell18/`, тесты - в `tests/`.
В `run.sh` настроен путь импорта пакета; `Makefile` содержит цели `run`
и `test`. В `DEFENSE.md` приведены порядок демонстрации и ответы для защиты.

Каждый этап сохранен отдельным коммитом с тегом:

| Тег | Результат этапа |
| --- | --- |
| `stage-1` | CLI REPL, реальные пользователь/хост, парсер, заглушки `ls`/`cd`, `exit` и ошибки |
| `stage-2` | Параметры VFS/скрипта, отладочный вывод, комментарии и сценарии запуска |
| `stage-3` | Загрузка XML/base64 VFS в память, проверки формата, примеры источников |
| `stage-4` | Реальная логика `ls`, `cd`; новые `tree`, `cal`, `pwd`; сценарий режимов/ошибок |
| `stage-5` | `mkdir`, `chown`, изменения только в памяти; сценарий режимов/ошибок |

Просмотр истории без изменения рабочей копии:

```sh
git log --oneline --decorate
git tag --list 'stage-*'
git show stage-1:src/shell18/shell.py
```

Эмулятор реализует указанный учебный набор команд. Конвейеры,
перенаправления, запуск процессов, подстановка команд, шаблоны `*`,
ссылки, права доступа и сохранение изменений на диск не реализованы.
Несколько изменений в одной команде применяются последовательно:
ошибка позднего пути не откатывает уже обработанные пути. Работа с VFS
ограничена доступной памятью, а загрузка XML использует рекурсию
с проверкой ошибки чрезмерной вложенности. Команда `tree` обходит дерево
через явный стек, поэтому не ограничена глубиной стека вызовов Python.
